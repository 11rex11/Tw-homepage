# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
If `GLOSSARY-MAP.md` exists, follow it to the relevant context glossaries.

When these documents are absent, proceed silently.
Create them through domain modeling when terms or decisions are resolved.

## Layout

This repository uses a single-context layout:
- `GLOSSARY.md` at the repository root
- Architecture decision records under `docs/adr/`

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts.
Reconsider unfamiliar terminology or record real gaps for domain modeling.
Explicitly identify any proposal that conflicts with an existing ADR.
